# R4 Workflow — Critical Risk

## Workflow

执行完整 S0~S9：

1. S0 完整需求治理和需求评审。
2. S1 完整规格 delta 和规格评审。
3. S2 `design.md` + ADR + 数据/契约/失败模式设计和架构评审。
4. S3 WBS、测试策略、迁移/回滚和发布策略，通过 Plan Review。
5. 建立 Delivery Profile；只有存在至少两个无共享状态、可独立测试的批次时才启用 isolation gate。
6. 若启用并行，先完成 DAG：节点/依赖、拓扑层、关键路径、所有权、扇出、收敛点和集成顺序；各批次使用隔离 worktree。
7. S4 TDD 实施；关键路径优先，不因并行延迟。
8. S5 单元 + 集成 + 契约 + 迁移 + 静态检查 + required gates 专项验证。
9. S6 Code Review + 安全/数据/合规/架构专项评审。
10. S7 在 DAG 收敛点集成，解决接口/Schema/契约冲突并全量回归。
11. S8 apply/archive + delivery + observability：Feature Flag/灰度、回滚条件、发布审批、监控基线、告警阈值、观察窗口和停止条件。
12. S9 记录 JSONL Metrics，按 CLAUDE.md 报告。

## Constraints

- 多 Agent 是交付策略，不是 R4 判定条件；不适合并行时使用单 Agent 串行。
- 不可逆迁移、无回滚路径、缺少发布后观测能力时，不得进入交付。
- 规格或评审能力降级必须先获得用户明确批准。
