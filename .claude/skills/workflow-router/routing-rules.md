# Routing Rules

## 1. Minimum Level Rules

以下任一条件成立，最低为 L2：

- 跨微服务
- 跨多个业务模块且存在业务耦合
- 数据库 Schema 发生重要变化
- 数据迁移
- Kafka 等消息链路变化
- Redis 分布式一致性/锁/幂等逻辑
- 订单状态机
- 库存扣减/释放
- 支付链路
- 权限模型
- 跨服务事务/一致性
- 重要异步流程
- 对外核心 API 契约变化

## 2. Direct L3 Rules

以下任一条件成立，默认 L3：

- 微服务拆分或合并
- 核心系统架构重构
- 大规模数据迁移
- 核心交易链路整体重构
- 多服务同时进行结构性改造
- 需要多个 Agent 并行开发
- 需要多个隔离工作区
- 大规模模块边界重构
- 关键基础设施替换

## 3. Risk Override

如果业务风险明显高于代码修改范围，以风险为准。

例如：

“只修改库存扣减的一行代码”

即使 Scope 很小，也不得自动判定为 L0。

## 4. User Override

用户可以明确要求：

`L0 / L1 / L2 / L3`

但高风险任务不得因为用户指定低 Level 就绕过安全要求。

如果用户要求降低等级，应说明被跳过的保护措施，并要求确认。

## 5. Upgrade

实现过程中发现复杂度增加：

L0 → L1
L1 → L2
L2 → L3

立即升级。

## 6. Downgrade

不允许静默降级。

如果可以降低复杂度，应先说明：

- 原因
- 被移除的流程
- 风险变化

再等待确认。
