# Adaptive Routing Policy

路由顺序是“风险下限 → Fast 准入 → Standard 默认”，不使用主观总分。

## Governed: any trigger is enough

只要本次变更实际改变以下任一语义，最低为 Governed：

- 资金、库存、身份认证、授权、隐私、敏感数据或监管行为
- 公共 API/事件契约的不兼容变化，或多个服务必须协调上线
- Schema 迁移、数据回填、双写、切流、停机或难以验证的历史数据修复
- 全局安全策略、共享基础设施默认行为或核心架构边界
- 缺少可信回滚路径，或失败会造成严重且难恢复的影响
- 跨多个仓库/团队交付，且任一方的版本或发布顺序影响正确性

以下因素也可将 Standard 升级为 Governed：影响面无法可靠界定、消费者众多、需要多个相互依赖的实施批次、关键测试环境不可用。

关键词本身不是证据。例如读取支付状态不等于改变资金语义。

## Fast: every condition must hold

只有同时满足以下条件才进入 Fast：

- 目标和验收标准明确，不需要产品或架构取舍
- 修改局限于一个局部，直接消费者清晰
- 不改变公共契约、持久化 Schema、权限、安全边界或关键业务语义
- 变更易回滚，失败影响有限
- 存在一个直接、可信且成本较低的验证方式

典型任务：文案、局部样式、无行为语义的配置、小范围明确 Bug、测试补充、机械性重命名。

## Standard: the default

不满足 Fast 且未触发 Governed 的任务进入 Standard，例如：

- 普通功能、CRUD、兼容性接口扩展
- 跨多个文件或同一模块内多组件协作
- 有限的业务规则、状态变化或错误处理调整
- 需要设计选择但影响范围和回滚路径明确
- 依赖升级、构建调整或团队共享配置变更

## Overrides and unknowns

- 用户可以要求更高模式。
- 用户要求更低模式不能绕过 Governed 触发器；必须明确会失去的规格、评审和验证后再请求确认。
- 关键信息未知时先用 Standard 做定向探索；未知本身在高影响区域可触发 Governed。
- 代码量只影响探索和执行深度，不会抵消行为风险。
