# L3 Workflow — Full Engineering

## Suitable For

- 架构变更
- 微服务拆分
- 核心交易链路
- 大规模重构
- 多服务结构性变更
- 多 Agent 协作
- 高风险数据迁移

## Workflow

### 1. Full Repository Understanding

分析：

- Architecture
- Module boundaries
- Dependencies
- Data model
- API contracts
- Async messaging
- Cache
- Transaction boundaries
- Observability
- Deployment/runtime constraints

### 2. Superpowers

使用 Superpowers 的完整工程工作流完成分析、设计、规划、验证和执行。

### 3. OpenSpec

创建完整 Change：

- Proposal
- Design
- Specs
- Tasks

必要时补充 ADR 或项目架构文档。

### 4. Plan

形成可执行的工程计划。

每个任务明确：

- Owner/Agent
- Dependencies
- Files/Modules
- Acceptance Criteria
- Tests
- Verification

### 5. Plannotator Plan Review

人工审核：

- 需求是否完整
- 设计是否合理
- 是否存在遗漏
- 是否存在过度设计
- 是否存在数据/一致性风险
- 是否允许并行开发

未批准不得开始实现。

### 6. Execution

根据任务依赖决定：

- 串行
- 并行
- 多 Agent
- 独立 worktree

不要为了使用多 Agent 而强行并行。

### 7. Verification

至少覆盖：

- Unit Test
- Integration Test
- Contract/API Test（适用时）
- Data migration validation（适用时）
- Build
- Static checks
- Critical path verification

### 8. Integration

合并各任务结果，解决：

- 冲突
- 接口不一致
- Schema 不一致
- Event contract 不一致
- 测试失败

### 9. Plannotator Code Review

进行最终人工 Review。

### 10. Finalization

完成：

- Final verification
- PR/Merge
- OpenSpec archive
- Documentation update
- Change summary
